## 範圍與版本

本階段完成文件閱讀、現況盤點、共用資料結構與可驗證的規則基礎。修改留在既有 `demo` 安全開發分支；開始時工作目錄乾淨，基準 commit 為 `276482d`。未提交、推送、合併或部署。

已閱讀三份 PDF：原始討論稿 4 頁、整理稿 `(1)` 4 頁、最新 `SalesBrain_決賽共識與Demo規格.pdf` 49 頁（v1.0，2026/10/08）。開發授權以使用者貼上的任務為準，資料與算法採最新規格；簡報與競賽提交要求只作背景，不是本次要執行的動作。

使用者要求優先於參考文件：首頁維持簡潔，九功能集中百寶袋；教學素材可先用可操作的示範動畫。目前 VID01 僅有元資料，尚無可播放資產，沒有聲稱影片已製作。

四大目標為三系統整合、降低行政工時、傳承經驗、新手即戰力。整合是共用基礎；其餘三目標各有三功能，總計九個。不增加獨立窗口、主管後台、語音或真實模型 API。

## 規則與語意決策

- 固定未來模擬快照 `2026-10-20T09:00:00+08:00`；主檔／Call 更新 08:55、銷售 08:00；文件依個別日期。
- Call 按客戶計，同業務／月份、valid 且 completed，以 ID 去重。V002 引用 CALL002 不重算。全部客戶 8/13 實際 61.54%、7/13 封頂 53.85%、3/5 達標 60%，缺口合計 6。
- 篩後摘要與明細一致；A 級零 Call 只剩 C001，0/4、缺 4。UI 若另保留全月總覽，須標明「全部客戶」。缺規則或其他月份分母未知，不冒充 0%。
- 十月已請款含稅金額 28,500、目標 40,000、71.25%；九月 29,000。A/B/C 數量變化 +20%/-25%/+50%。九月全月與十月至 20 日不等長，不推論同比、下降原因或月底預測。
- 僅有整體業務十月目標；篩產品／客戶後不自行分攤或套用整體目標當子項達成率。

## 本地操作與部署

`npm run dev` 開終端機 Local 網址。`npm test` 驗證新規則；`npm run build` 建置。PowerShell 若封鎖 npm.ps1，可使用 npm.cmd，不必改系統執行策略。

規則測試使用 Node 原生 TypeScript stripping，建議 Node 24，本次實測 v24.18.0。現有 GitHub 工作流程僅 build；加入 CI 測試時須同步設定可支援 stripping 的 Node 版本。

收到部署授權後才可 `npm run deploy` 或合併推送 main。前者會發布當前分支的工作目錄，後者觸發既有工作流程。部署前仍需完成後續 UI 與瀏覽器驗收。
